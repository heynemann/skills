# Bruno: try the API by hand

[Bruno](https://www.usebruno.com/) is an open-source API client. Its collections
are plain files in the repo. Each service ships a Bruno collection **generated
from `api/openapi.yaml`**, so every operation is ready to send against a local
server, with no hand maintenance and no drift from the spec.

It is for exploring and debugging by hand. Automated checks stay in Go tests and
the curl smoke test in the verification gate.

## Layout

```text
api/bruno/environments/local.yml   # hand-written: the only Bruno input you edit
gen/bruno/                         # generated by `make generate-bruno`, committed, never edited
  opencollection.yml               #   collection root (OpenCollection YAML, Bruno 3+)
  environments/local.yml           #   copied from api/bruno/environments
  <tag>/folder.yml                 #   one folder per spec tag (= feature)
  <tag>/<OperationId>.yml          #   one request per operation
```

The format is OpenCollection YAML (`.yml`), Bruno's default since 3.0. The
classic `.bru` format is not used.

## Environment

`api/bruno/environments/local.yml`

```yaml
name: local
variables:
  - name: baseUrl
    value: http://localhost:8080/v1
  - name: token
    secret: true
```

- Every generated request URL is `{{baseUrl}}/<path>`. `baseUrl` includes the
  `/v1` prefix.
- Operations that declare `security: [bearerAuth: ...]` get
  `auth: {type: bearer, token: "{{token}}"}` (auth.md). `secret: true` means the
  value is stored encrypted on each developer's machine and never written to the
  file. Keep the variable even without auth: it costs nothing.
- To add an environment (e.g. `compose.yml` with a different port), add a file
  here and run `make generate-bruno`. Changes made to environment files in the
  app are overwritten on the next generate: edit `api/bruno/environments/`
  instead.

## Generation

Two Node tools run through `npx`, pinned to exact versions in the Makefile
(tooling.md) so `make check-generated` is reproducible:

1. `@redocly/cli bundle` inlines the `./common.yaml` references into a temporary
   single-file spec. `bru import` doesn't resolve external `$ref`s: without
   bundling, the shared `limit`/`cursor` query parameters are silently missing.
2. `@usebruno/cli import openapi` writes the collection into `gen/bruno`. Its
   generated `Environment 1.yml` (with `baseUrl: /v1`, unusable) is replaced by
   `api/bruno/environments/`.

The output is deterministic, so `make generate` is part of `check-generated`.
When you scaffold, pin each tool to its latest version
(`npm view @usebruno/cli version`, `npm view @redocly/cli version`) and bump
them on purpose.

## What the generated requests contain

| From the spec | In the request |
| --- | --- |
| tag | folder |
| `operationId` | request name and file name |
| request body schema | JSON body; each field is its `example` or empty (`""`) |
| query parameter with `default` | enabled with that value (`limit=20`) |
| query parameter without `default` | present but disabled (`cursor`) |
| path parameter | `:projectId` param, empty until you fill it in |
| `security` | bearer auth with `{{token}}` |
| responses | saved examples (status and JSON shape) |

So that requests can be sent as generated, give every request-body property and
optional query parameter an `example` in the spec (openapi.md). kin-openapi
validates examples against their schema when the spec loads, so a wrong example
fails startup and the tests.

## Using it

1. `make migrate-up && make run`, or `docker compose up` (tooling.md).
2. In Bruno: **Open Collection** and pick `gen/bruno`, then choose the `local`
   environment (top right).
3. With auth: set the `token` value in the environment's Secrets tab.
4. Send `CreateProject`, copy the returned `id` into `GetProject`'s `projectId`
   path param, and so on.

Treat `gen/bruno` as read-only. Saving an edited request writes into it, and the
next `make generate` throws the edit away (`check-generated` flags it before
then). For ad-hoc requests you want to keep, use a separate personal collection
outside the repo.

Same collection from the terminal (optional, not part of the gate):

```sh
cd gen/bruno
npx -y @usebruno/cli@<pinned> run --env local                                 # whole collection
npx -y @usebruno/cli@<pinned> run projects/ListProjects.yml --env local  # one request
npx -y @usebruno/cli@<pinned> run --env local --env-var token="$TOKEN"         # with auth
```

Requests with empty path params send the literal `:projectId` and get a 400 from
the validator. The CLI is for quick pokes, not a test suite.
